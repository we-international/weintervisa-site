# Wix → static site (learned 17 Nov 2026)

## Export blog posts (read-only)
- Wix Blog `POST https://www.wixapis.com/blog/v3/posts/query` with `fieldsets: ["RICH_CONTENT","SEO","URL"]`, sort `firstPublishedDate DESC`, `paging.limit` ≤ 100.
- Convert Ricos → Markdown **inside** ExecuteWixAPI (PARAGRAPH, HEADING, lists, BLOCKQUOTE, DIVIDER, IMAGE, TABLE; TEXT decorations BOLD/ITALIC/LINK). Return a `unknown` node-type counter so nothing is lost silently (we found 1 VIDEO → `{{youtube ID}}`).
- ExecuteWixAPI truncates results over ~25k tokens (~100k chars) and the JSON breaks. Page it: 37 posts ≈ 120k chars → 2 calls of 19. Large tool output is saved to a file → parse it with Python instead of re-typing (saves tokens).
- `seoData.tags`: title tag = `type:"title"` (`children`), description = `type:"meta"` with `props.name=="description"`. Many posts have none → fall back to title/excerpt.
- The live post URL is `https://www.weintervisa.com/post/<slug>` (`fieldsets URL` confirms it).

## Keep every URL
- GitHub Pages serves `/post/<slug>` from `post/<slug>.html` (no trailing slash, no redirect) → write that file, not `post/<slug>/index.html` (that adds a 301 to `/slug/`).
- Same feed path as Wix: `/blog-feed.xml`. Old home `/welcome` → `/`. Static redirects = meta refresh + canonical + noindex.
- Turn absolute links to our own domain into site-relative links so the preview host works.
- A link test over all built pages finds dead links that are **already broken on Wix** (17 Nov: Head On post → missing "what's on in October" post). Redirect them to /blog and report.

## Preview safety
- Preview build: `<meta name=robots content=noindex>` on every page + `robots.txt Disallow: /`; no CNAME until the owner approves the DNS day. `--production` flips both.
- Sandbox can't reach weintervisa.com or static.wixstatic.com (proxy 403) → images look broken in local screenshots; copy them with `tools/fetch_images.py` from CI before the switch (Wix media may stop after the plan ends).
  - How (21 Nov 2026): workflow **"Copy Wix images into the repo"** (`.github/workflows/fetch-wix-images.yml`, `workflow_dispatch`, `contents: write`). The runner downloads the images, fails if any `static.wixstatic.com` link is left, runs the tests and pushes a NEW branch `claude/local-images-<run id>` committed as We International (never main). Then open a PR from that branch; a push made with `GITHUB_TOKEN` does not start CI, so add one small commit yourself (or re-run) so the PR checks run, then fast-forward main.
  - A workflow file must be on main before `workflow_dispatch` can run it: merge the workflow first, trigger it second.
  - `tests/test_site.py` counts Wix-hosted post images ("must be 0 before the DNS switch") and fails if a post points at a local image that is not in the repo.

## Checks (tests/test_site.py + tests/e2e.mjs)
All Wix slugs exist · no broken internal links (pages still to build listed separately) · no personal name/email, only info@weintervisa.com · no trackers/cookies · footer: company name, QEAC number only, "not a migration agent" · feed/sitemap counts · phone 375px + desktop: status, one h1, no sideways scroll.
- In ESM tests, load the global Playwright with `createRequire(import.meta.url)("playwright")` (NODE_PATH does not work for `import`).

- 2026-11-20: the preview lives at a project page (we-international.github.io/weintervisa-site/), so root-relative links (/assets/site.css, /post/...) broke and the page showed unstyled. The Pages workflow now rebuilds with `SITE_BASE=/weintervisa-site` before upload (build.py `apply_base_path`, preview only). Tests still run on the plain build. Drop the step on the DNS day (custom domain serves from the root).

## Live Wix vs new site (learned 21 Nov 2026)
- Workflow **"Live Wix vs new site"** (`.github/workflows/live-vs-new.yml`, runs on PRs that touch it or its tools, and by hand once on main). The runner reads the live sitemap (`tools/live_urls.py`: sitemap index → pages / blog-posts / blog-categories) and pushes `tests/wix-live-urls.json` + side-by-side screenshots (`tools/compare_shots.mjs`, Wix left, new right, phone + desktop) to an **orphan** branch `review/compare-<run id>` (never merged). Fetch it with `git fetch origin review/compare-<id>` and `git --work-tree=<dir> checkout FETCH_HEAD -- review`.
- `tests/test_site.py` then fails if any live sitemap URL is not a page or redirect in the new build (owner-pending app pages listed in `tests/pending-pages.json`). Re-run the workflow before the DNS day: the blog keeps getting new posts on Wix.
- First run found: 1 new post published on Wix after the export, 3 blog category pages `/blog/categories/<slug>`, and Wix app pages `/members` and `/file-share` (not in the first inventory). Categories: Wix Blog `GET https://www.wixapis.com/blog/v3/categories` + `categoryIds` on posts → `content/blog-categories.json` → chips on /blog and one page per category.
- Wix answers fast repeat visits from a datacenter with a bot check ("Please wait while we verify your request", ~17 words). Only the first page came through. The script waits up to 30 s for it to clear, goes slowly (6 s between live pages) and marks rows "(Wix bot check)". Do not try to get round it; screenshots from a normal browser are the fallback.
- Word counts on the live Wix page are near 0 even when it renders (content sits in an embed), so compare by the screenshot, not by text metrics.
- The live Wix pages are custom embeds (iframes) and are newer and much fuller than the CMS drafts we first rebuilt from (21 Nov run: home 1,312 words live vs 424 new, homestay 1,157 vs 151, fast-track 1,003 vs 199). The compare run saves each live page's text (`review/compare/text/<page>.txt`) and the markup of its main frame (`<page>.html`, scripts removed) so pages can be rebuilt from what visitors see. Rebuild from those, not from the CMS drafts.

## Rebuilding a page from the live Wix page (learned 21 Nov 2026, home v2)
- Source = `review/compare-<run>/text/<page>.txt` (what visitors read) + `<page>.html` (links, image URLs + alt, hidden FAQ answers inside `<details>`; extract them with a small regex script, the .txt only has the questions).
- Put the page's words in `content/<page>.json`, the layout in Python. Keep owner rules over live wording (e.g. live "talk to us in your language" → "Mia chats in your language; our team replies in Thai or English"). Drop `utm_*` parameters (no analytics), the Wix translate widget (we have the EN/TH switch) and YouTube thumbnails from i.ytimg.com (link to the video instead of loading a Google image).
- Images: list them as `{"wix": <url without /v1/fill...>, "file": "<id>-mv2.<ext>", "alt": ...}`. `home_page.img()` renders an `<img>` only when `assets/img/<file>` exists, so the page never loads from Wix and works before the copy. `tools/fetch_images.py` (workflow "Copy Wix images into the repo") also downloads every `{"wix","file"}` in `content/*.json`; its "no Wix links left" check looks at `content/posts` only.
- Test the rebuild against the live page: body word count ≥ live (home: 1,457 vs 1,312), every path/CTA link resolves, no `utm_`, the AI-character disclaimer is kept.
- Wix originals behind the live embeds are big (Maya & Kenji scenes: 2048 px PNG, 3.6–3.8 MB). Name the local copy `…-mv2.webp` in `content/*.json`: `fetch_images.py` then re-encodes to WebP ≤1400 px, q80 (≈150 KB). Don't merge multi-MB PNGs into the repo: if a run already pushed them, take its branch, re-encode, and amend before it reaches main.
- `/fast-track-courses` (Working Holiday) rebuilt the same way (`fasttrack_page.py` + `content/fast-track.json`, 1,208 words vs live 1,003). The Wix 3-question JS course finder became a one-question picker of links that jump to the course card (`#chc33021`, `:target` outline) — no script needed.

## Go-live (DNS day) — learned 22 Nov 2026
- Runbook: `docs/go-live.md` (owner presses; team prepares). One switch: `config.json` `"live": true` → `pages.yml` builds `--production` (no `SITE_BASE`); `false` = preview under `/weintervisa-site/` with noindex.
- `tests/test_production.py` runs in CI on every PR: robots Allow + sitemap, no noindex on real pages (redirect stubs stay noindex), canonical = own `https://www.weintervisa.com/...` URL, hreflang/sitemap/feed on the real domain, no `/weintervisa-site` or github.io left, CNAME, every live Wix URL answers, only approved schools, forms connect only with the anon key. It builds with `SITE_BASE` set to prove production ignores it, then rebuilds preview.
- Order on the day matters: set the Pages custom domain → merge the `live: true` PR and wait for deploy → *then* change DNS. Changing DNS first serves the preview build (base path, noindex) to real visitors.
- With Actions-deployed Pages the `CNAME` file is ignored: the custom domain is set in Settings → Pages (owner). Verify the domain at org level first (TXT `_github-pages-challenge-<org>`) to block takeovers. HTTPS cert comes only after DNS points at GitHub (minutes–1 h) → pick a quiet hour, then Enforce HTTPS.
- The cloud run cannot resolve DNS (proxy blocks dns.google, the site, dig). Workflow "DNS snapshot (read-only)" digs from the runner; read it with the GitHub MCP `get_job_logs`. 22 Nov snapshot: NS Wix, `@` A 185.230.63.x, `www` CNAME cdn3.wixdns.net, MX Google, SPF + google-site-verification, **no DKIM, no DMARC** (flagged to the owner as a separate free fix).
- GitHub Pages targets: A 185.199.108–111.153, AAAA 2606:50c0:8000–8003::153, `www` CNAME `<org>.github.io`. Rollback = put the Wix records back (Wix stays published until the plan ends).

## Publish a NEW post on the live Wix blog before the DNS day — learned 24 Nov 2026
- Until DNS moves, a time-critical post (e.g. a rule that starts on a date) must go on **live Wix** *and* into `content/posts/` so the new site has it on the same URL. Do both in one run.
- Source of truth = the `.md` in `content/posts/<slug>.md` (approved text only; replace "[publish date]" placeholders with today; keep the AI label). Links absolute to `https://www.weintervisa.com/...` and only to pages that exist on Wix today (`/th/...` pages do not exist on Wix yet → use `/contact-us`).
- Wix call (ExecuteWixAPI, site `412bcdd9-…`): `POST https://www.wixapis.com/blog/v3/draft-posts?fieldsets=URL` with `{draftPost:{title, memberId, categoryIds, language:"en", seoSlug, excerpt, richContent, media, seoData}, publish:true}`. With `publish:true` it is live when the call returns 200; confirm with `GET /blog/v3/posts/{id}` (`firstPublishedDate`). Never resend: every call makes a new post → query recent posts for the slug first inside the same function.
- `memberId` = the author of the existing posts (read it from `posts/query`); `categoryIds` from an existing post in the same category; reuse an existing cover `media.wixMedia.image.id` when the topic matches (no upload).
- Ricos: send the markdown through the `files` param and convert inside the JS (or `tools/md_to_ricos.py` offline): HEADING holds TEXT directly, LIST_ITEM → PARAGRAPH → TEXT, decorations `LINK{linkData.link{url,target:"BLANK"}}`, `BOLD{fontWeightValue:700}`, `ITALIC{italicData:true}`. 30 nodes worked first try.
- A Thai + English post is one post (EN first, "ภาษาไทย" heading below): the Wix blog is English-only and `/th/blog` lists English post URLs anyway.
- Then in the repo: add the slug to `tests/wix-post-slugs.json`, its category in `content/blog-categories.json`, and `/post/<slug>` to `tests/wix-live-urls.json` (otherwise feed/sitemap counts fail). The cloud run cannot open weintervisa.com (proxy 403) — the API read-back is the check.
- FAQ answers in `faq_page.GENERAL` are escaped; a trusted link is allowed only as the answer's last part (`…</a>`) and the FAQPage JSON-LD strips it to plain text.
- 28 Nov 2026 (IMMI-20261118-4, second post the same way, 48 nodes, first try): read `GET /blog/v3/posts/slugs/<slug>` first for `memberId`, `categoryIds` and a cover from a post on the **same topic** (the 8503 cover is named `visitor-8503`, so a WHM post reused the "WHM ballot" cover). Put the slug check + create + read-back in ONE function; it returns `status: PUBLISHED` and `firstPublishedDate`. Set the repo post `date` to that timestamp.
- Before this, check the repo history: IMMI-20261117-3 was already live since 24 Nov (PR #33) while its AI Office task still said `blocked`. Close such tasks with the live URL instead of publishing twice.
- A deep immi link written by another team ("…/latest-news/<new-page-slug>") that the cloud run cannot open (WebFetch blocked, page is JS) and that web search does not return is **not** linked: link the parent page that lists it (`/what-we-do/whm-program/latest-news`) plus a search-verified Home Affairs news URL, and say so in the task log.
- 28 Nov 2026 (IMMI-20261128-4, $1,500 onshore application charge): a visa post that has **not** passed CQA-002 yet does not go on Wix. Draft the `.md` on a branch `claude/<post>` and push it, but open **no PR**: `tests/test_site.py` fails (feed/sitemap/blog counts) until the slug is in `tests/wix-post-slugs.json` + `tests/wix-live-urls.json`, and those may only list posts that are live on Wix. Put the same text in a Google Doc for CQA, set the task to `review` with a "ตรวจเองแล้ว" line, and say the branch name in `next`. After CQA: publish on Wix, register the slug, open the PR from that branch, merge on green.
- Read the official text yourself, not only the IMMI alert. For F2026L01607 the explanatory statement (Attachment C) put subclass 590 in Class TU, which the alert still called "not confirmed". When the ES words a point two ways (Pacific exemption: "certain classes" vs "all affected subclasses"), write the narrower wording. Leave out a link you could not open (the visa pricing estimator URL) rather than guess it.

## Posts other teams publish on Wix — learned 28 Nov 2026
- Other teams (immigration/content) also publish straight to the live Wix blog. 28 Nov: `/post/visa-questions-when-to-talk-to-a-registered-migration-agent` (live 26 Nov) was missing from the new site, and no test caught it because `tests/wix-live-urls.json` is only a snapshot from the last compare run.
- Every run: one read-only `POST /blog/v3/posts/query` (sort `firstPublishedDate DESC`, limit 10) → list slugs → `ls content/posts/<slug>.md`. Any missing → `GET /blog/v3/posts/slugs/<slug>?fieldsets=RICH_CONTENT&fieldsets=SEO&fieldsets=URL`, convert Ricos → markdown inside the function (return an `unknown` node counter; must be `{}`), map `categoryIds` with `GET /blog/v3/categories`.
- Then the usual three list edits (slug in `tests/wix-post-slugs.json`, category `posts` in `content/blog-categories.json`, `/post/<slug>` in `tests/wix-live-urls.json`). Edit those JSON files as text (insert one line): re-dumping them with `json.dump` changes the indentation of the whole file.
- Keep the date = Wix `firstPublishedDate`; cover = the Wix image id with `~mv2` → `-mv2` (check `assets/img/` has it, else `fetch_images.py` copies it later).
- Guard since 28 Nov 2026: workflow **"Wix drift (daily)"** (`.github/workflows/wix-drift.yml`, 06:17 Sydney + by hand) builds the site and runs `tools/live_urls.py --strict` from the runner: exit 1 = a live Wix sitemap URL is missing in the new build. Read-only (`contents: read`, no push). Each run, check its latest result with `gh api "repos/we-international/weintervisa-site/actions/workflows/wix-drift.yml/runs?per_page=1" --jq '.workflow_runs[0].conclusion'`; red → the job summary lists the missing paths → copy them as above. Wix may answer the runner with its bot check; if the sitemap read fails the run is red too: re-run once by hand before acting.
